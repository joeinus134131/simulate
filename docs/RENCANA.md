# Rencana perombakan ArduSim

## Audit baseline (13 September 2026)
- Frontend Next 16 / React 19, Three/R3F, Zustand; backend Go/Fiber. Tidak ada AGENTS.md pada proyek.
- Katalog aktual: Uno R3, breadboard 30 kolom, LED merah, tombol 4 kaki, potensiometer, resistor 220Ω, jumper merah/hitam/biru/hijau/kuning (11 entri, 7 bentuk).
- Geometri awal tersedia untuk semua, tetapi header Uno berbeda dari definisi pin dan tidak punya target wiring. Breadboard menerapkan posisi pin dua kali dan lubang berada di tengah badan. Target pin beradius 1.5 jauh melebihi jarak antar-pin 0.5.
- Engine regex/new Function berjalan pada UI, memetakan D13 ke semua LED dan D2/A0 ke sensor pertama tanpa kabel. millis tidak mengikuti delay; stop tidak membatalkan delay. Serial hanya echo.
- Backend health tersedia, proyek dan AI adalah mock. Belum ada penyimpanan frontend atau tes.
- Perubahan pengguna sudah ada di frontend package/lock, layout, CSS, page dan tema; dipertahankan.

## Kontrak dukungan yang dituju
Simulasi pendidikan DC kuasistatik pada satu Uno virtual dengan catu ideal 5V/3.3V, digital/PWM rata-rata, analog 10-bit; resistor linear, LED model tegangan maju perkiraan, pot pembagi resistif, tombol sakelar ideal, breadboard/jumper kontinuitas. Tidak mencakup SPICE/transien, suhu/kerusakan, toleransi komponen, CPU AVR cycle-accurate, library C++ pihak ketiga, I2C/SPI/UART fisik, USB atau regulator Vin. Fitur yang tidak dimodelkan harus dijelaskan, bukan berpura-pura berjalan.

## Referensi fisik
Uno R3: https://docs.arduino.cc/hardware/uno-rev3/ dan https://content.arduino.cc/assets/A000066-full-pinout.pdf ; dimensi PCB 68.6 × 53.4 mm, pitch header 2.54 mm. Skala adegan 1 unit ≈ 5 mm. Komponen generik memiliki variasi kemasan; bukan CAD produksi bersertifikasi.

## Addendum implementasi Physical AI (4 Oktober 2026)

Dokumen ini mencatat audit baseline ArduSim awal. Roadmap produk yang berlaku kemudian diperinci pada `README.md` dan dokumen 01–06; status awal Tahap 2–6 di atas tidak menggambarkan branch terbaru. Implementasi mengikuti milestone M0 pada README sebelum fitur robotika.

### M0 — sinkronisasi runtime
- **Selesai di kode:** `SimulationClock` fixed-step 5 ms (200 Hz); jam sketch `millis()`/`micros()`, `delay()`/`delayMicroseconds()`, dan timer Wi-Fi virtual mengikuti sim-time; UI menerima frame rata-rata 60 Hz; pause menghentikan sim-time. Handle Servo punya state per objek dan kini menelusuri koneksi sinyal lewat breadboard, jumper, dan wire.
- **Keputusan keamanan:** akses jaringan bebas dari sketch diblokir; API HTTP kompatibilitas menyatakan jaringan dinonaktifkan. Konektor eksternal kelak harus melewati gateway dengan kebijakan izin domain.
- **Validasi lokal:** checkpoint sebelum sensor bridge: `npm test` lulus **63 checks**, termasuk fixture kinematika 10.000 pose, exp/log SE(3), Jacobian finite-difference, fixed-step/pause/delay/replay, routing V-HAL, ISR encoder, motor R-L, battery OCV/ESR/SoC, pembebanan SG90/L298N/A4988, sag rail Uno dan state machine BOR, RC termal/shutdown driver, serta clamp diode flyback. Setelah sensor bridge, validasi ulang tercatat di bagian sensor di bawah. `npx tsc --noEmit`, lint terarah pada file fitur termasuk worker dan panel baterai, serta production build `npx next build --webpack` pernah lulus pada checkpoint thermal L298N sebelum clamp diode eksplisit. Build default Turbopack gagal di sandbox saat child process mencoba membuka port (`Operation not permitted`); build Webpack berhasil. Benchmark lokal 1.000 target sebelumnya: DLS pose mean 0.113 ms/max 1.755 ms; DLS posisi mean 0.341 ms/max 0.908 ms (bukan jaminan di setiap hardware).
- **Validasi tambahan A4988/DC supply (5 Oktober):** TypeScript, lint pada file driver/solver/worker/panel, dan production build terisolasi lulus setelah penambahan driver. Belum ada golden test integrasi A4988 melalui sketch atau cek arus terhadap simulator rangkaian rujukan; jangan anggap akurasi elektrik sudah tervalidasi.
- **Validasi encoder/ISR (5 Oktober):** TypeScript, lint terarah, dan production build terisolasi lulus setelah kopling encoder–motor dan API interrupt. Preset A4988 + NEMA17 + encoder disediakan; eksekusi sketch end-to-end belum menjadi regression test. Callback dihasilkan oleh state perubahan rangkaian, bukan CPU cycle-accurate. Mode `LOW` dipicu ketika pin masuk LOW (satu callback per transisi), dan satu perubahan sudut dibatasi maksimum 256 edge callback.
- **Kopling actuator-joint:** panel Servo/Stepper/DC motor dapat memetakan sudut ke salah satu joint EduArm/AeroArm dengan offset, arah, serta batas joint. Motor DC mengambil posisi shaft output dari integrasi gearbox. Ini pemetaan state kinematik; belum ada mounting link, torsi balik atau dynamics robot-joint. TypeScript, lint terarah, dan production build lulus untuk perubahan Servo/Stepper; regresi runtime kopling belum dijalankan.
- **RGB-D kamera sintetis:** komponen `rgbd_camera` menangkap scene Three.js pada 320×240 (default) atau 640×480, menghasilkan RGBA dan `Float32Array` depth dalam meter serta intrinsics fx/fy/cx/cy. Capture menggunakan dua render pass dan sampling 10 Hz simulation time; panel menampilkan RGB/depth preview dan statistik frame. Depth saat ini dienkode 24-bit di GPU lalu diekspansi ke Float32 di CPU, jadi presisi sumbernya 24-bit (bukan render attachment Float32). Setiap capture memiliki sequence monotonik agar pose-triggered frame yang datang pada timestamp sim-time yang sama tetap diteruskan ke worker. Shim sketch menyediakan `cameraDepth`, `cameraRgb`, `cameraWidth`, dan `cameraHeight`. Transfer structured clone menyalin buffer; belum ada zero-copy, `/dev/video0`, atau validasi depth terhadap fixture.
- **LiDAR planar sintetis:** komponen `planar_lidar` meraycast scene 360° setiap 100 ms sim-time, dengan 360 atau 720 sampel dan batas jarak 4–30 m. Frame berisi `Float32Array` jarak dan mask hit; panel menampilkan peta top-down. Snapshot terbaru dikirim ke simulation worker dan shim sketch menyediakan `lidarRange`/`lidarHit`. Raycast belum memakai BVH, noise/intensitas belum dimodelkan, tidak ada bus/perangkat fisik; hasil runtime belum divalidasi.
- **IMU sintetis 6-axis:** komponen `imu_6axis` menghitung akselerometer specific-force (termasuk gravitasi) dan gyro dari perubahan pose sensor, RoverBot, atau end-effector arm. Noise Gaussian deterministik memakai seed per sensor; frekuensi target 25/50/100 Hz dibatasi kedatangan state UI (maksimum praktis sekitar 60 Hz). Snapshot terbaru tersedia di simulation worker melalui shim `imuRead`. Sensor belum mengikuti pose rigid-body Rapier atau menambah bias drift; belum ada Python/AI worker untuk frame IMU, integrasi sensor end-to-end pada sketch belum diuji dan implementasi IMU belum melalui validasi numerik.
- **Validasi sensor worker (5 Oktober):** tes `SketchRuntime` membaca frame RGB-D, LiDAR, IMU, indeks di luar batas, ID tak dikenal, dan snapshot terbaru. Helper signature memasukkan sequence untuk RGB-D, LiDAR, dan IMU, sehingga frame pose-triggered pada timestamp sama tetap terkirim. Preset baru `sensor_fusion` memberi Uno + RGB-D/LiDAR/IMU dan sketch Serial untuk mencoba API sensor tanpa wiring. Smoke test visual browser sebelumnya melihat RGB-D 320×240 dengan 37.440/76.800 depth pixel valid, LiDAR 149/360 hit (min 4.00 m), dan IMU diam dengan specific-force sekitar 9.8 m/s² pada sumbu vertikal. Percobaan browser terisolasi menampilkan “Loading 3D space…” saat dev server sempat gagal menemukan import `PlanarLidarSensor`; log setelah hot reload menunjukkan route kembali 200. Host Mac kini terkunci sehingga UI belum bisa diperiksa ulang. Akurasi depth terhadap fixture dan uji browser end-to-end masih terbuka; structured clone menyalin buffer.
- **L298N + motor DC gearbox:** `l298n_dual_hbridge` membaca input arah/enable dari net, menerapkan drop transistor nominal 2 V dan menampilkan arus/rugi daya dengan warning >2 A. Arus motor memengaruhi arus node VS baterai pada fixed-step. Heatsink mengikuti RC termal orde satu, memberi warning pada 90 °C, thermal shutdown pada 150 °C dan recovery pada 135 °C. Empat diode clamp per dual H-bridge membatasi OUT di luar rel GND/VS dan menyediakan jalur flyback. `dc_motor` memakai ekuivalen R-L/back-EMF per solver step dan integrasi putaran fixed-step 5 ms, rasio 1:48, torsi beban, serta encoder opsional. Switching PWM, current limit aktif dan validasi terhadap motor rujukan masih belum ada.
- **Validasi L298N + motor DC (5 Oktober):** test solver membuktikan daya logika/catu dikenali, arus motor bertanda sesuai polaritas, dan kedua arah putaran bekerja; test V-HAL memeriksa R-L ekuivalen serta kenaikan kecepatan/back-EMF/posisi pada 40 langkah. Tes perilaku ini tidak menyatakan parameter tervalidasi terhadap datasheet atau motor fisik.
- **Battery pack + BOR (5 Oktober):** battery pack Li-ion 18650/LiPo 2S/alkaline 9V menerapkan kurva OCV tipikal, ESR, kapasitas, SoC discharge, switch, telemetri arus/daya dan warning arus alkaline tinggi. Resistor, transient/holding SG90, daya fase A4988, dan armature current L298N dibebankan pada node pack. Rail board eksternal memicu reset saat melewati ambang; output MCU dilepas dan sketch baru berjalan setelah rail pulih dengan hysteresis. Tes solver mencakup beban resistif, motor DC, winding A4988, dua servo alkaline 9V serta sag yang melintasi threshold Uno; tes V-HAL menguji akumulasi waktu/hysteresis, bukan keseluruhan worker end-to-end. BOR bekerja pada resolusi fixed-step 5 ms, kurva belum divalidasi sel fisik, dan DC supply tetap ideal.
- **L298N thermal/freewheel model (5 Oktober):** model RC heatsink orde satu memanaskan dari daya loss yang dihitung solver, warning ≥90 °C, mematikan output pada 150 °C dan melepas shutdown di bawah 135 °C. Empat clamp diode/kanal tersedia dengan VF 0.7 V; tes solver memastikan tegangan coast terjepit pada rail dan arus clamp tercatat. Unit test mencakup warm-up/cool-down dan H-bridge tidak menggerakkan motor saat shutdown. Belum ada validasi termal terhadap datasheet/heatsink fisik; model switching PWM tetap kuasistatik.
- **Golden kinematika ModernRoboticsPython (5 Oktober):** dependency `modern_robotics==1.1.1` dan NumPy dipasang ke lingkungan validasi sementara, lalu script `frontend/scripts/verify-kinematics-reference.py` membandingkan 10.000 konfigurasi FK/SE(3)/Jacobian dan 250 target reachable pose + position-only DLS dengan reference `FKinSpace`, `MatrixExp6`, `MatrixLog6`, `JacobianSpace`, dan `IKinSpace`. Maksimum error FK `1.944e-16 m` / `5.095e-16 rad`, exp `9.992e-16 m` / `8.017e-16 rad`, log `3.767e-14`, Jacobian `6.661e-16`; pose-DLS `9.992e-05 m` / `1.585e-05 rad`, position-DLS `9.994e-05 m`. Pada reproduksi terakhir p95/max DLS `0.271/1.777 ms` pose dan `0.374/3.540 ms` position, di bawah batas 5 ms pada host uji. Position-only solver memakai 120 iterasi, damping 0.025, max step 0.1 rad, dan coordinate nudge deterministik untuk keluar dari singularitas arm lurus. `npm test` lulus **76 checks**, termasuk recovery singularitas dan invariant root/panjang link FABRIK pada 200 target reachable plus target unreachable; FABRIK memang tidak memiliki algoritma rujukan di ModernRoboticsPython. Lint terarah, TypeScript, dan production build Webpack juga lulus. Reproduksi: `python3 -m pip install -r requirements-kinematics-reference.txt`, lalu `npm run test:kinematics-reference` dari `frontend`.
- **P0 yang sudah ada di kode:** PoE FK, SO(3)/SE(3) exp/log, Jacobian space/body, DLS pose/posisi dengan joint limits, FABRIK, trajectory quintic; EduArm-3DOF dan AeroArm-6DOF tampil di katalog/canvas dengan kontrol joint, target XYZ, serta IK posisi di worker. RoverBot-4WD menghitung differential-drive pose dan fase roda memakai sim-time, dan tersedia kontrol panel serta handle `DifferentialDrive` pada sketch.

Junction estimate memakai rugi konduksi dua MOSFET per fase (RDS(on) maksimum 0.86 Ω per lintasan), RθJA 32 °C/W dari datasheet Allegro untuk PCB empat lapis, dan Cθ 0.5 J/°C sebagai asumsi transien edukasi. Shutdown aktif pada 165 °C dan pulih di bawah 150 °C; VDD UVLO memakai ambang falling 2.71 V/rising 2.8 V; setelan >2.1 A melatch OCP hingga VREF diturunkan dan SLEEP disikluskan atau VDD diputus. Tes helper mencakup kurva termal, UVLO hysteresis dan pelepasan fault. Short fisik antar terminal belum dideteksi, chopping PWM/winding R-L tidak dimodelkan, dan RθJA bergantung layout nyata.
- **Validasi sensor + A4988 (5 Oktober):** `npm test` lulus **65 checks**, termasuk API frame lewat `SketchRuntime`, pembacaan snapshot terbaru setelah frame berubah, proteksi OCP/UVLO A4988, dan kurva RC shutdown/recovery. TypeScript, lint terarah, dan production build Webpack lulus setelah sensor bridge dan model A4988. Belum ada uji browser-worker yang menangkap render/raycast asli dan memvalidasi kedalaman atau IMU numerik; transfer snapshot memakai structured clone.
- **Regulator DC-DC buck-boost (5 Oktober):** komponen terpisah mengubah VIN 2.5–24 V ke rail 3.3/5/9/12 V, efisiensi 90%, batas arus keluaran 0.25–3 A (default 2 A), dan telemetry. Solver memakai active-set CV/CC untuk menurunkan tegangan saat beban di atas batas; arus input dihitung dari daya output dan diterapkan ke battery ESR pada solver pass selanjutnya di fixed-step yang sama. Tes mencakup sag pack setelah current draw converter diserap dan rail Uno 5V dari baterai satu sel, serta droop/current-limit. Tidak ada switching ripple, soft-start, reverse power/charging, atau regulator internal MCU. Validasi saat ini `npm test` 68 checks; TypeScript, lint dan production build Webpack dijalankan pada checkpoint ini.
- **Proteksi pack dan charger CC/CV (5 Oktober):** `battery_pack` punya batas discharge yang dapat dikonfigurasi dengan nilai awal 5 A untuk Li-ion 1S, 10 A untuk LiPo 2S, dan 0.5 A untuk alkaline 9V. Kelebihan arus memutus pack dan menyimpan arus trip sampai tombol Reset proteksi ditekan. Komponen baru `battery_charger` menerima input catu DC dan koneksi BAT+/BAT−; Li-ion 1S memakai cutoff 4.2 V, LiPo 2S 8.4 V, arus dibatasi slider 0.05–2 A, lalu taper CV mengikuti OCV/ESR pack. Arus bersih masuk ke integrasi SoC; alkaline ditolak. Pada implementasi awal belum ada temperatur atau proteksi polaritas; keduanya kini ditambahkan pada butir berikutnya. Cell balancing dan profil sel tertentu masih belum ada. Tes terdahulu mencakup proteksi arus pack, CC, taper CV dan penolakan alkaline. `npm test` saat itu lulus **69 checks**, TypeScript, lint terarah, dan production build Webpack juga lulus; hasil tersebut belum mencakup perubahan charger berikutnya.
- **Proteksi thermal/polaritas charger (5 Oktober):** charger memperkirakan rugi konversi dari arus keluaran dan efisiensi, mengintegrasikan suhu package lewat jaringan RC edukasi (35 °C/W, 8 J/°C), mematikan charge pada 90 °C, dan pulih setelah suhu turun di bawah 75 °C. Tegangan input negatif atau terminal BAT yang tersilang memblokir arus dan menampilkan fault; proteksi adalah ideal, tanpa diode/reverse-current. Regresi solver menguji kedua tipe koneksi terbalik dan test model RC mencakup shutdown/hysteresis/recovery. Sesudah perubahan ini `npm test` lulus **71 checks**, lint terarah lulus, `npx tsc --noEmit` lulus dan production build `npm run build -- --webpack` lulus. Balancing sel dan validasi hardware masih terbuka.
- **Terminasi tail-current charger (5 Oktober):** CV menghentikan arus saat turun di bawah 0.05C pack (minimum 0.02 A), menandai pengisian selesai, dan resume ketika SoC di bawah 98%. Panel menampilkan status `Complete` dan ambang tail current. Regresi solver mencakup terminasi dan resume; bagian ini termasuk di suite **72 checks** bersama Virtual Soldering Workbench. Cell balancing edukasional ditambahkan setelah checkpoint ini.
- **LiPo 2S per-cell SoC dan passive balancing (5 Oktober):** pack menyimpan SoC/OCV kedua sel, menampilkan slider SoC tiap sel, beda tegangan, sel yang sedang diseimbangkan dan arus bleed. Saat terhubung ke charger yang valid dan delta OCV ≥30 mV, sel yang lebih tinggi menerima model bleed 50 mA; arus CC/CV ikut dibatasi headroom sel tersebut dan bleed dikurangkan dari integrasi SoC. Nilai 30 mV/50 mA merupakan asumsi pendidikan yang belum divalidasi terhadap hardware dan bukan safety monitor/proteksi overvoltage individual. Regresi memastikan telemetry 4.2/4.1 V, delta 100 mV, balance 50 mA, arus charge dan penurunan SoC sel tinggi; checkpoint ini lulus **73 checks**. Timer charger dan validasi hardware masih terbuka pada checkpoint tersebut.
- **Safety timer charger (5 Oktober):** timeout edukasional menghitung waktu charge aktif berdasarkan sim-time, default 10 jam dan dapat diubah 1–24 jam. Saat habis, charger memutus charge, memberi warning dan menunggu reset manual; waktu saat charger idle tidak dihitung. 10 jam adalah asumsi simulator yang dicontohkan dari timer tetap pada [TI BQ2405x](https://www.ti.com/product/BQ24052), bukan universal atau tervalidasi untuk hardware yang disimulasikan. Tes mencakup akumulasi, pause, latch/reset behavior, dan solver lockout; gabungan charger/LiPo suite lulus **74 checks**. Proteksi fisik dan validasi hardware tetap terbuka.
- **V-HAL I2C, PCA9685, dan grafika SSD1306 (5 Oktober):** `Wire` menyediakan TX/RX 32 byte, ACK/NACK, dan API Arduino standar; ACK memerlukan alamat, SDA/SCL aktual tersambung ke bus MCU dan perangkat bertenaga. SSD1306 `0x3C` init, invert, address-window, dan framebuffer 1-bit dikirim melalui I2C control byte dalam frame ukuran maksimum 32 byte. Framebuffer 128×64 dikemas menjadi 1024 byte, ditransformasikan ke urutan page/column controller, dan divisualkan pada texture OLED; GFX mendukung 5×7 ASCII dasar, pixel, line, rectangle, circle, triangle, bitmap, clear, dan invert. `Wire` langsung menangani control byte command/data, rentang kolom/halaman, mode alamat, penulisan GDDRAM, display on/off, dan inverse; command argument dapat melintasi transaksi. LCD PCF8574 `0x27` tetap dikunci ke bus/power. IMU berpin listrik dan register MPU-6050 `0x68` mengembalikan snapshot accel/gyro signed 16-bit. PCA9685 `0x40` memiliki modul katalog/3D dengan 16 pin kanal, `Adafruit_PWMServoDriver.begin`, `setPWMFreq`, `setPWM`, state register 12-bit, prescaler/frekuensi, pin OE aktif-low, dan menggerakkan servo tersambung dengan pulsa 1000–2000 µs. Preset I2C scanner memasang LCD/OLED/PCA9685/IMU dan menjalankan probe alamat 7-bit lewat `Wire`; test mock-runtime sekaligus memastikan keempat alamat tersambung ke SDA/SCL dan rail daya. Regresi mencakup transaksi/chunk/NACK, framebuffer/raster/layout, parser command mentah, ACK/wiring/power, register/ticks, OE, preset, scanner dan dispatch handle sketch. `npm test` lulus **92 checks**, TypeScript/lint terarah dan production build Webpack lulus. Gelombang PWM belum dimasukkan ke MNA; command controller lainnya, validasi worker-browser end-to-end, serta multi-master masih terbuka.
- **V-SBC Python Pyodide (5 Oktober):** file `.py` pada editor memakai Monaco Python dan menjalankan runtime pada worker terpisah; Circuit Worker yang sama menjalankan solver pada mode firmware eksternal. `Jetson.GPIO` memetakan BCM ke pin board Uno/ESP32 terpilih, dengan setup/input/output, pull-up, PWM dan cleanup; input membaca snapshot voltase terminal dan output/PWM diterapkan pada V-HAL. `cv2.VideoCapture(0)` mengambil frame RGB-D RGBA terbaru (max 20 Hz ke worker), membalik origin tekstur dan mengembalikan BGR top-left ke OpenCV. AST Python menambahkan yield kooperatif ke loop `for`/`while` serta `time.sleep`, sehingga pause/resume dan stop dapat dijalankan. Checkpoint V-SBC sebelumnya lulus **92 checks**, termasuk Pyodide lokal yang menjalankan script dan cooperative yield serta I2C scanner. Node sandbox gagal mengakses CDN pada uji wheel, jadi OpenCV import, kamera aktual, GPIO melalui browser dan integrasi worker belum diverifikasi end-to-end. - **Async AI Gateway dan Colab starter (5 Oktober):** panel gateway menghubungkan URL `wss://` yang dimasukkan pengguna (plain `ws://` hanya untuk localhost). Pada laju 5/10 Hz, klien mengirim frame RGB JPEG terpilih maksimum 320×240, waktu/sequence frame, ID kamera, dan posisi joint robot terpilih; kode proyek, wiring, serta kredensial tidak disertakan. Klien menolak payload malformed/di atas 16 KB, sequence duplikat/lama, target robot/index yang tidak sesuai, membatasi durasi 50–2000 ms, meng-clamp posisi ke batas joint URDF-lite, dan menginterpolasi memakai sim-time sehingga pause membekukan gerak. Notebook `public/ai-gateway/colab_starter.ipynb` membuka WebSocket melalui ngrok; kredensial tunnel diminta lewat hidden input. Fungsi contoh hanya mengembalikan pose saat ini sebagai kebijakan hold agar pengguna dapat menguji koneksi tanpa gerak; model harus mengganti `infer_action`. Unit test memeriksa validasi payload, clamping dan URL, tetapi gateway/tunnel maupun notebook belum diuji di browser/Colab. Ini asynchronous action-chunk transport, bukan loop kontrol cloud real-time.
- **ONNX edge inference tahap awal (5 Oktober):** panel menerima satu file ONNX maksimum 100 MB, memilih kamera, backend WebGPU/WASM, normalisasi unit/ImageNet, serta dimensi dinamis.
